# Style and typography rules

## Preserve the reference hierarchy

Measure title, subtitle, module headers, body copy, callouts, captions, footers, and page numbers independently. Do not infer one global font size. For Chinese scientific slides, prefer Microsoft YaHei, DengXian, SimHei, Source Han Sans, or Noto Sans CJK according to the reference. Use Cambria Math for editable formula approximations.

## Text-box discipline

- Horizontal margin: usually `0.12–0.18 in`.
- Vertical margin: usually `0.08–0.12 in`.
- Card-body line spacing: `1.15–1.25`.
- Paragraph-after spacing: about `2 pt`.
- Avoid automatic character-by-character wrapping.
- Split long sentences deliberately into two or three semantic lines.
- Increase text-box width before shrinking the body font.
- Do not let secondary labels collide with the primary KPI value.

## Repeated cards

Align number circle, icon center, title baseline, first body line, and bottom padding across all cards. Keep corner radius, border weight, card height, and gaps constant unless the target shows a deliberate exception.

## Icons

When using reference crops: crop only the icon; retain antialiasing pixels; remove near-white/neutral background without erasing white icon details; inspect a contact sheet; record crop coordinates; preserve aspect ratio. Do not include nearby titles, separators, borders, or shadows.

## Connectors

Keep arrows editable, route around node boxes and text, and use consistent line width/arrowheads. Use dashed connectors only when the reference or logic distinguishes collaboration, guidance, feedback, or non-primary paths.

## KPI cards and charts

Give the main value a dedicated centered line. Put secondary values in separate editable badges. For a diagrammatic bar chart, use editable rectangles, grid lines, category labels, ticks, and value texts. Widen the category-label zone and remove unnecessary spaces around `/` before reducing font size.

## Color semantics

Derive colors from the target. Preserve any semantic system consistently, for example blue for primary flow, green for resolved/success, orange for developer action or warning, purple for quality control, and red for risk or deletion. Do not introduce gradients, extra shadows, or decorative colors absent from the reference.
